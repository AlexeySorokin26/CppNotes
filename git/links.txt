ref ссылка это имя которое указыаает на коммит 
Всё, что я перечислял — это и есть ссылки, разные виды:

ветка IP-3908-revision-copy — ссылка
снимок origin/IP-3908-revision-copy — ссылка
HEAD — ссылка
тег v1.0 — тоже ссылка

Это как слово «мебель»: нет предмета «мебель», есть стул, стол, шкаф. «Ссылка» — это «мебель», 
а ветка/origin/HEAD — это стул/стол/шкаф. Когда я писал «зачем придумали ссылки», 
я фактически спрашивал «зачем вообще придумали имена для коммитов» — и ответ был про это: чтобы коммит можно было найти и чтобы ручка пережила смену хеша.


git push --force говорит серверу: «переклей свой стикер на мой коммит. Куда он сейчас указывает — не смотрю, просто делай». 
Если кто-то (другая твоя машина, коллега, CI) успел добавить коммиты в эту ветку на сервере — их стикер указывал на них, ты его уволок на своё, и те коммиты осиротели. Ты стёр то, чего даже не видел.

git push --force-with-lease говорит: «переклей на мой коммит, но сначала проверь — стикер на сервере (#3) всё ещё там, где у меня в снимке (#2)? 
Если да — безопасно, клей. Если сервер уехал дальше моего снимка — СТОП, там есть что-то, чего я не видел».

«stale info» = эта проверка не прошла. #3 ≠ #2. Lease затормозил именно для того, чтобы ты вслепую не затёр чужой коммит.

Прикладной итог для тебя: git fetch обновит #2 до фактического #3.
