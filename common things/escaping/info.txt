Экранирование (escaping) — это когда символ, у которого в каком-то контексте есть особое значение, 
ты заменяешь на безопасную запись, чтобы он воспринимался как обычные данные, а не как часть синтаксиса.

Проблема всегда одна и та же: в тексте перемешаны две вещи — сам контент и управляющие символы формата. 
Парсер должен как-то различать «это буквы, которые надо показать» и «это команда формату». Для этого договариваются, что некоторые символы — служебные.

В HTML служебные — это в первую очередь <, >, &. 
Когда браузер (или Qt в rich-text режиме) видит <, он думает «начинается тег». 
Поэтому если в данных есть имя папки a<b, оно прочитается как «текст a, потом открывается тег b...», и разметка поедет.

Экранирование заменяет такие символы на их «entity»-записи, которые рендерятся как сам символ, но парсером за синтаксис не принимаются:
&  →  &amp;
<  →  &lt;
>  →  &gt;
"  →  &quot;

То есть строка Tom & Jerry после экранирования становится Tom &amp; Jerry

QString::toHtmlEscaped() как раз делает эту замену

Реальный пример
QString GroupAverageCurvesDialog::MakeChipTooltip(const QString& subject, const QStringList& timePoints) {
    QStringList tp = timePoints;
    tp.sort(Qt::CaseInsensitive);

    const bool dark = IsDarkMode();
    const QString titleColor = dark ? "#f1f3f4" : "#1f1f1f";
    const QString textColor = dark ? "#e8eaed" : "#202124";

    return QStringLiteral("<b style='color:%1;'>%2</b><br><span style='color:%3;'>%4</span>")
        .arg(titleColor, subject.toHtmlEscaped(), textColor, tp.join(", "));
}

QStringLiteral("<b ...>%2<br><span ...>%4</span>")
                ▲              ▲
          это написал ТЫ   сюда .arg() вставит имя папки

<b> — это символы, которые набрал ты сам, своими руками, в исходнике. 
Ты набрал <, b, > именно потому, что хочешь жирный шрифт. 
Qt читает твой < как «начало тега» — и это ровно то, что тебе нужно. Всё сработало как задумано. Трогать нечего.

%4 — это дыра. Ты не знаешь, что туда попадёт. Туда .arg() подставит строку, которую вернула файловая система. 
Может там 004h. А может там имя a<b. И вот если там окажется <, то Qt прочитает его так же, как твой < — «начало тега». 
Но ты-то этого < не писал и тега там не хотел! Это просто буква из имени папки. 
Qt не умеет отличить «<, который автор набрал нарочно» от «<, который случайно приехал в данных» — для него оба одинаковы.

Вот в этом вся суть. Экранирование — это способ сказать Qt: «эти символы пришли из данных, читай их как буквы, а не как команды». 
toHtmlEscaped() превращает < в &lt;, и Qt показывает значок < вместо того, чтобы искать тег.

Rich text vs plain text
Plain text — это чистая последовательность символов, и больше ничего. 
В "привет" нет информации о том, какого он цвета, шрифта, размера, жирный или нет. 
Просто шесть букв. Файл .txt, содержимое QLineEdit, аргумент std::cout << — всё это plain text: символы есть, оформления нет.

Rich text — те же символы плюс метаданные об оформлении: 
этот кусок жирный, этот красный, здесь перенос абзаца, тут заголовок, там таблица. Word-документ, HTML-страница, тултип с <b> — это rich text.

Теперь к Qt конкретно. У Qt есть свой диалект rich text — подмножество HTML 4 + немного CSS (Qt зовёт это «Qt-supported HTML subset»). 
Виджеты вроде QLabel, QToolTip, QTextEdit умеют его рендерить: жирный, курсив, цвета, <br>, ссылки, простые таблицы, <img>
