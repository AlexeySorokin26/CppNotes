# Бинарный поиск (lower_bound / поиск по половинам) — конспект

## 1. Задача

Есть **отсортированный** массив. Нужно найти **первый индекс**, где
`cdf[i] >= r` (первый элемент, не меньший искомого `r`).

Это ровно то, что делает `std::lower_bound(begin, end, r)`.

Пример (CDF из Scan.md, правые границы отрезков):

```
индекс:  0     1     2     3
cdf:    0.1   0.6   0.7   1.0
r = 0.65  ->  первый >= 0.65 это 0.7  ->  индекс 2
```

### Зачем это нужно
Scan дал отрезки на оси `[0,1)`:

```
отрезок:  [0.0, 0.1)  [0.1, 0.6)  [0.6, 0.7)  [0.7, 1.0)
воксель:      0           1           2           3
```

Бросаем случайное `r` и ищем, в какой отрезок попало. Отрезок, чья
**правая граница** первой оказывается `>= r`, и есть ответ.
`r = 0.65` попадает в `[0.6, 0.7)` → воксель 2.

## 2. Два названия: бисекция и бинарный поиск

Одна и та же идея («деление пополам») пришла из двух областей, отсюда
два имени:

- **Бинарный поиск** (binary search) — термин из **программирования**.
  `binary` = «из двух»: каждый шаг делит данные на **две** части и одну
  выбрасывает.
- **Бисекция** (bisection) — термин из **вычислительной математики**.
  Латинское `bi` (дважды) + `sectio` (разрезание) = «рассечение надвое»,
  буквально «деление пополам».

Это не два алгоритма, а одно действие под двумя именами.

### Строго говоря — два контекста
- **Бинарный поиск** — дискретный: ищем **индекс** в отсортированном
  массиве. Ответ — целое. Шагов `log2(N)`.
- **Метод бисекции** — непрерывный: ищем **корень** функции `f(x)=0` на
  отрезке `[a,b]`, где `f` меняет знак. Ответ — вещественное. Делим
  пополам, пока отрезок не станет уже заданной точности.

```
бинарный поиск         метод бисекции
массив [lo, hi)         отрезок [a, b]
cdf[mid] < r ?          f(mid) < 0 ?
ответ = индекс          ответ = x (корень)
```

Ключ один — **монотонный признак**: `cdf[i] < r` сначала «истина»,
потом «ложь», как `f(x)` меняет знак. Поэтому наш `LowerBound` можно
звать и так, и так. Исторически binary search — дискретный аналог
метода бисекции.

## 3. Почему именно lower_bound (нижняя отсечка диапазона)

Имя — про **границы диапазона одинаковых элементов**, а не про
«меньше/больше по значению». Если значение повторяется, повторы
занимают целый кусок массива; у него две границы:

- **`lower_bound(v)`** — **нижняя** (левая) отсечка: первый `>= v`
- **`upper_bound(v)`** — **верхняя** (правая) отсечка: первый `> v`

```
индекс:  0   1   2   3   4
массив:  1   3   3   3   5
             ^           ^
   lower_bound(3)=1   upper_bound(3)=4
             └─── диапазон троек [1,4) ───┘
```

- `[lower, upper)` = весь диапазон равных → это `std::equal_range`
- `lower` = где значение начинается, `upper` = первый за ним

`lower_bound` даёт нижнюю отсечку, **даже если значения в массиве нет** —
тогда это просто место, куда его вставить, а диапазон равных пустой:

```
ищем v = 4 в  1 3 3 3 5
lower_bound(4) = upper_bound(4) = индекс 4  (перед 5)
диапазон [4,4) пустой — четвёрок нет, но вставить 4 надо сюда
```

Поэтому `lower_bound` возвращает первый `>= v`: крайнюю левую позицию,
куда `v` впишется без нарушения порядка. У нас в CDF повторов нет и `r`
почти всегда «между» значениями — то есть просто первый отрезок, чья
правая граница дотянулась до `r`.

## 4. Код (device-совместимый)

```cpp
// Первый индекс, где cdf[i] >= r. Аналог std::lower_bound,
// но без итераторов — работает и на GPU (CURRENT_MODALITY).
CURRENT_MODALITY inline int64 LowerBound(const CVector<const float>& cdf, double r) {
    int64 lo = 0, hi = cdf.Size();          // ищем в [lo, hi)
    while (lo < hi) {
        const int64 mid = lo + (hi - lo) / 2;  // (hi - lo)/2 вместо (lo+hi)/2: без переполнения
        if (cdf[mid] < r)
            lo = mid + 1;                   // r правее mid
        else
            hi = mid;                       // cdf[mid] >= r — кандидат
    }
    return lo;
}
```

### Почему `lo + (hi - lo) / 2`, а не `(lo + hi) / 2`
Математически одно и то же, но `lo + hi` на больших индексах может
переполнить тип. `lo + (hi - lo)/2` переполнения не даёт.

### Почему не `std::lower_bound`
`std::lower_bound` работает на CPU, но не компилируется в CUDA-ядре.
Своя версия на индексах (а не итераторах) идёт и на host, и на device.
