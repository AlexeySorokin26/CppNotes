Шаблоны и раздельная компиляция

Суть: шаблон — это рецепт, а не код. Машинные инструкции появляются только при инстанцировании (использование с конкретным типом: add<int>). Без использования шаблон в код не превращается.

Почему не работает определение в .cpp:

cpp
// add.cpp
template<typename T> T add(T a, T b) { return a + b; }  // никто не инстанцирует в этом TU

// main.cpp
add(1, 2);  // нужен add<int>

Что создаётся при компиляции:

main.cpp: видит объявление из заголовка → сигнатура известна, вызов принят «на веру» → создаётся запрос на символ add<int> (неразрешённая ссылка). Самого символа тут нет.
add.cpp: видит определение, но никто не инстанцирует → символ не генерируется вообще. В add.o для add пусто. Определение осталось лежать как текст-рецепт.

Итог по add<int>: запрос есть (в main.o), символа нет нигде.

Компиляция проходит, падает ЛИНКОВКА ← ключевой контринтуитивный момент:

g++ -c main.cpp    # ок → main.o
g++ -c add.cpp     # ок → add.o
g++ main.o add.o   # ← undefined reference to add<int>

Оба .o создаются без ошибок. Линкер приходит, видит запрос, идёт искать — не находит. Ошибка линкера, не компилятора. (Ошибка компиляции была бы только если main.cpp вообще не видел объявления — тогда add было бы неизвестным именем.)

Отличие от обычной функции: определение обычной функции в .cpp само по себе становится символом в .o, без всякого использования → линкер её находит. Обычная функция — готовое блюдо; шаблон — рецепт, который готовится только под конкретный заказ.

Решения:

Определение в заголовке (стандарт) — каждый TU сам инстанцирует что нужно. ODR ослаблено, дубликаты дедуплицируются линкером (weak/COMDAT).
Явное инстанцирование в .cpp:
cpp
   template int add<int>(int, int);   // символ физически появится в add.o

Минус: заранее знать список типов. Плюс: спрятать реализацию, ограничить типы, ускорить сборку.
3. Шаблон определён + использован в одном .cpp — работает (инстанцирование прямо там).

Аккуратный вариант: реализация в .tpp/.inl, #include в конце заголовка — функционально = в заголовке.
