Почему нужно явно прописывать std::move 

Потому что категория значения (lvalue/rvalue) относится к выражению, а не к типу переменной.

SomeClass &&someClass объявляет переменную типа «rvalue-ссылка на SomeClass». Но выражение someClass внутри тела — это имя переменной, а любое выражение-имя является lvalue. Правило простое: если у выражения есть имя, это lvalue.

cpp
B(SomeClass &&someClass)
    : someClass(someClass)            // decltype(someClass) == SomeClass&&,
                                      // но выражение someClass — lvalue → copy ctor
    : someClass(std::move(someClass)) // static_cast<SomeClass&&>(someClass) → xvalue → move ctor

Сделано так ради безопасности. Именованный объект можно использовать несколько раз:

cpp
B(SomeClass &&s) : a(s), b(s) {}

Если бы s неявно считалось rvalue, первое использование (a(s)) украло бы data, и b получил бы nullptr. 
Поэтому язык требует явно сказать «здесь можно забрать ресурс» через std::move, который по сути просто static_cast<T&&>. 
Тип && в параметре лишь гарантирует, что снаружи передали временный объект (или явно move-нутый), а внутри функции это обычный именованный объект.
