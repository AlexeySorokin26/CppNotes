Почему anonymous namespace 
https://cppguide.ru/misc/anonymous-namespaces/

По умолчанию все глобальные переменные (не константы) и свободные функции получают внешнее связывание (external linkage) и их имена видны компоновщику.
Одинаковые имена в разных модулях вызывают ошибки компоновщика. 
До введения С++11 для избежания коллизий имен из разных модулей использовалось ключевое слово static, которое делало имя "невидимым" за пределами модуля.

// Файл .cpp (C++98)
static int localCounter = 0;
static void MyFunction() { /* ... */ }

Однако static слишком перегружен и используется в разных контекстах:
    Локальные статические переменные внутри функций.
    Статические члены класса.
    Статические глобальные переменные/функции.

Важно! Анонимные пространства имен не отменяют внешнее связывание, 
но добавляют сущностям уникальное, сгенерированное компилятором имя, 
которое гарантированно не пересекается с именами из других единиц трансляции.

Не используйте анонимные пространства в заголовочных файлах!

Это создает серьезные проблемы с ODR (One Definition Rule) и раздуванием кода.
