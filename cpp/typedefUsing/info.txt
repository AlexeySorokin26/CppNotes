typedef — из C, то есть был всегда.
typedef нельзя параметризовать шаблоном
Решалось так
template<typename StatInfo>
struct MultiDict {
    typedef std::multimap<std::string, StatInfo> type;
};
// использование: typename MultiDict<StatInfo>::type
Тут кстати typename потому что dependent name and two-phase lookup
Когда компилятор парсит тело шаблона, он ещё не знает, 
чем является MultiDict<StatInfo> — тип зависит от параметра StatInfo, инстанцировать его на этом этапе нельзя. 
Значит, он не может понять, что такое ::type внутри:
вложенный тип (typedef, вложенный класс)?
или статический член / значение?

стандарт говорит: зависимое квалифицированное имя (X::something) считается не типом, если явно не написать typename
То есть typename — это «поверь мне, это именно тип».

Классический пример, откуда растёт неоднозначность:
template<typename T>
void foo() {
    T::x * y;   // что это?
}

T::x * y; читается двояко:

объявление указателя y на тип T::x (если T::x — тип);
выражение-умножение: T::x (статический член) умножить на y.
это именно declaration-vs-expression неоднозначность

using — C++11 (2011)
template<typename StatInfo>
using MultiDict = std::multimap<std::string, StatInfo>;

Для не-шаблонного случая using и typedef полностью эквивалентны — оба дают псевдоним (не новый тип), никакой семантической разницы. 
Разница только в читаемости: 
using Callback = void(*)(int); 
против typedef void (*Callback)(int); — имя слева, а не закопано в середине.
