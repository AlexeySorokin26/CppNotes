Two phase lookup 
В шаблонном коде мы проходим TU один раз но чуть хитрее 

void foo(double);

template<class T>        // (1) встретил определение шаблона:
void f(T t) {            //     парсит, строит AST с "дырами",
    foo(1);              //     связывает независимые имена → фаза 1 для f
    bar(t);
}

void g() { /* обычный код */ }   // компилируется как обычно

int main() {
    f(42);               // (2) использование f<int> → запрос на инстанцирование
}
                         // (3) фаза 2 для f<int>: подстановка T=int,
                         //     lookup зависимых имён, кодогенерация

Фаза 1 происходит когда компилятор дошел до определения шаблона. 
Фаза 2 происходит когда шаблон с конкертным T понадобился 
обычный код между фазами компилируется как обычно

Зачем вообще это нужно? 
1 Конечно выявить синтаксически ошибки в независимых именах 
2 Строит базы для любых инстанцирований 

template<class T>
void f(T t) {
    print(1);       // уже решено: print(double), одинаково для всех T
    t.run();        // дыра: "вызвать run у t"
    T::type x;      // дыра (с typename): "какой-то тип"
}

Фаза 2 берёт эту заготовку и для каждого T делает копию, в которой заполняет дыры:

            заготовка f<T>  (фаза 1, один раз)
           /        |        \
     f<int>    f<Widget>    f<std::string>   (фаза 2, для каждого T)


Теперь зачем using 
Typedef нельзя сделать шаблоном это раз (можно но выглядит жестко)
typedef так не умеет, поэтому оборачивали в структуру

хотелось просто 
template<typename T>
typedef vec std::vector<T, MyAlloc<T>>;

но typedef не шаблонизирован
поэтому делаем такой костыль

template<class T>
struct Vec { typedef std::vector<T, MyAlloc<T>> type; };

используем 
class A{
    vec<int>::type v;
}

но если у нас внутри шаблон уже не собирается 
template<typename T>
class A{
    vec<T>::type v; // проблема зависимых типов по дефолту он будет думать что это значение некоторое (переменная грубо)
                    // мы же можем сделать переменную type например (так думает компилятор по дефолту) но найти ее не может
    
    // typename vec<T>::type v; // fix 
}

с using не нужно будет писать typename для компилятора 
template<typename T>
using vec = std::vector<T, MyAlloc<T>>; 
это исключительно название типа     




Классический пример, откуда растёт неоднозначность:
template <typename T>
void f() {
    T::a * b;           // это умножение T::a на b, а НЕ объявление указателя! НО если это объявление переменной a и такая есть то все ок
    typename T::a * b;  // вот теперь b — указатель на тип T::a
}

А вот тут не сработает 
template<class Container>
void f(Container& c) {
    Container::iterator it = c.begin();   // хочу переменную типа iterator
}
По правилу по умолчанию Container::iterator — значение.
Тогда значение it = ... не имеет смысла как выражение: после значения не может идти идентификатор.

Аналогично есть третья категория, шаблон. По умолчанию T::a не считается и шаблоном, поэтому для вложенного шаблона нужен template:
T::template rebind<int>   // без template '<' парсится как "меньше"
