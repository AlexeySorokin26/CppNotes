Три категории времени жизни (storage duration) в C++ ложатся ровно на эту картинку:

Автоматическое — локальные переменные и параметры. 
    Живут в кадре стека, создаются при входе в блок и уничтожаются при выходе. 
    Компилятор всё делает сам, ты не управляешь временем жизни явно.

Статическое — глобальные, static-переменные любой области видимости и thread_local. 
    Живут всю программу (thread_local — всё время жизни потока), инициализируются один раз. Именно они лежат в .data / .bss / .rodata.
    инициализированные в data, неинициализированные в bss.
    Количество глобальных переменных известно заранее, 
    поэтому память под них выделяется в специальных областях программы, отдельными и от стека и от кучи.
    Отличие data от bss в том, что data занимает место на диске в составе бинарника (до запуска программы), а bss нет.

Динамическое — то, что ты создаёшь через new/malloc. 
    Живёт в куче, время жизни контролируешь ты (или умный указатель).



int g_init       = 42;      // .data   — глобальная, ненулевой инициализатор
int g_zero       = 0;       // .bss    — ноль в файле хранить не нужно
int g_uninit;               // .bss    — без инициализации → тоже ноль
const int g_c    = 7;       // .rodata — const, read-only
const char* g_p  = "hi";    // сам указатель g_p → .data; "hi" → .rodata

static int s_file = 100;    // .data, при этом внутренняя линковка (см. ниже)

void foo() {
    static int s_local = 5; // .data — статическое время жизни, но видна только в foo
    int local = 3;          // стек
    int* p = new int(9);    // p (указатель) на стеке, а сам int(9) в куче
}
