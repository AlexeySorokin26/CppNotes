variadic templates (шаблоны с переменным числом параметров)

Ключевая идея — есть parameter pack (пакет), и есть его expansion (распаковка). 
Это разные вещи, и ... означает разное в зависимости от того, слева или справа он от имени.

template<typename... Size>    // pack типов: 0 или больше типов
void HostCall(Size... size);  // pack значений: 0 или больше аргументов этих типов

... слева от имени → «это пакет». А когда ты пишешь имя пакета в выражении с ... справа — это уже распаковка:


// база: один аргумент — возвращаем как есть
template<typename T>
T sum(T v) { return v; }

// голова + хвост
template<typename Head, typename... Tail>
auto sum(Head head, Tail... tail) {
    return head + sum(tail...);   // рекурсия: хвост на один короче
}

Tail... tail — это не один параметр. Многоточие меняет смысл: это «все остальные аргументы, сколько бы их ни было»

sum(1, 2, 3);
sum(1,2,3) -> 1 + sum(2,3)
                  -> 2 + sum(3)
                         -> 3
Fold expression C++17
template<typename... Args>
auto sum(Args... args) {
    return (args + ...);   // и всё
}

Ни базы, ни рекурсии. (args + ...) — это fold expression, свёртка.
Компилятор берёт пакет и расставляет между элементами +:

(args + ...)  →  1 + (2 + 3)

(args + ...)   // правая:  a + (b + (c))
(... + args)   // левая:  ((a) + b) + c

Для + разницы в результате нет. Но там, где порядок важен, — есть. Классика — вывод через <<, где нужна именно левая свёртка, чтобы аргументы печатались слева направо:

cpp
template<typename... Args>
void print(Args... args) {
    (std::cout << ... << args);   // ((cout << a) << b) << c
}

Распаковка пустого пакета даёт пустой список аргументов, и вызов схлопывается:

cpp
Parallelize(f, size...)   →   Parallelize(f)
